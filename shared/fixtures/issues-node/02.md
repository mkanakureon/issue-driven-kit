## 元の文書

- `docs/03-roadmap.md` の「優先的にテストする失敗ケース」と Phase 1
- `docs/api-contract.md`（いまの 4 つの API・エラーの形）

- `.claude/skills/design-cycle/SKILL.md`（設計書の形）・`docs/guides/decisions/test-plan.md`

## 合格の条件

- 設計書が `docs/guides/working/api-test-design.md` にある
- 「## 0.」の節にゴールと合格の条件がある
- 試験の名前の表があり、行の形は `` | `<試験の名前>` | 正常系 または 異常系 | <エンドポイント> | <期待する結果> | `` 。正常系が 4 本以上、異常系が 8 本以上。名前は重ならない
- 失敗ケース 8 つが全部、表のどこかの行か、「対象外（理由）」の節で扱われている（失敗ケースの番号 1〜8 を `失敗ケース N` の形で書く）
- 実装の Issue（正常系・異常系）の分け方と、それぞれの確認コマンドの案がある
- `src/`・`test/`・`docs/03-roadmap.md`・`docs/api-contract.md` を変えていない

```js
// 守る: docs/03-roadmap.md
// 守る: docs/api-contract.md
// 守る: src/worker.ts
import { readFileSync, existsSync } from 'node:fs';
import { check, gitClean, done } from './scripts/issue-run/check-lib.mjs';

const d = 'docs/guides/working/api-test-design.md';   // 書かせる文書は変数で指す
const t = existsSync(d) ? readFileSync(d, 'utf8') : '';
check(t.length > 0, `設計書がある: ${d}`);
for (const h of ['## 0.', 'ゴール', '合格の条件', '確認コマンド']) check(t.includes(h), `ある: ${h}`);
const rows = [...t.matchAll(/^\| `([^`]+)` \| (正常系|異常系) \|/gm)];
const normal = rows.filter((r) => r[2] === '正常系').length;
const abnormal = rows.filter((r) => r[2] === '異常系').length;
check(normal >= 4, `正常系の試験が 4 本以上（いま ${normal}）`);
check(abnormal >= 8, `異常系の試験が 8 本以上（いま ${abnormal}）`);
check(new Set(rows.map((r) => r[1])).size === rows.length, '試験の名前が重なっていない');
for (let n = 1; n <= 8; n++) check(t.includes(`失敗ケース ${n}`), `失敗ケース ${n} を扱っている`);
gitClean(['src/', 'test/']);
done();
```

## 先に決めておくこと

- 試験の名前は、`it('…')` にそのまま書く日本語の文にする（例: `GET /health が 200 と ok を返す`。#1 で作った試験も正常系の表に入れる）。
- いまの実装で扱えない失敗ケース（認証切れ・ネットワークの切断など）は、試験を作らず「対象外（理由）」の節に書く。
- スコア投稿の試験は、ローカルの `APP_ENV=local` の環境で動く形にする（試験の中で環境の値を与える）。
