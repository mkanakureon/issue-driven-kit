- 設計書の表の「正常系」の試験も、全部あって通る（#3 の分を消さない・弱めない）
- `node scripts/test.mjs` の最後の行が `Result: PASS`
- 設計書・`docs/api-contract.md`・`migrations/0001_initial.sql` を変えていない

```js
// 守る: docs/guides/working/api-test-design.md
// 守る: docs/api-contract.md
// 守る: migrations/0001_initial.sql
import { readFileSync, existsSync } from 'node:fs';
import { runTests, requireTests, check, done } from './scripts/issue-run/check-lib.mjs';

const d = 'docs/guides/working/api-test-design.md';
const t = existsSync(d) ? readFileSync(d, 'utf8') : '';
const rows = [...t.matchAll(/^\| `([^`]+)` \| (正常系|異常系) \|/gm)];
const abnormal = rows.filter((r) => r[2] === '異常系').map((r) => r[1]);
const normal = rows.filter((r) => r[2] === '正常系').map((r) => r[1]);
check(abnormal.length >= 8, `設計書の異常系が 8 本以上（いま ${abnormal.length}）`);
check(normal.length >= 4, `設計書の正常系が 4 本以上（いま ${normal.length}）`);
runTests();
requireTests([...normal, ...abnormal]);
done();
```

## 先に決めておくこと

- 試験の名前は設計書の表と一字も違えない（違うなら試験の側を表に合わせる。表は変えない）。
- 実装を直すときは、`docs/api-contract.md` のエラーの形（`{"error":{"code","message"}}`）とコードを守る。新しいコードが要るなら、直さずに「未採用の改善」に書く。
- 認証が要る失敗ケースは設計書で「対象外」になっているはず。試験を作らない。
