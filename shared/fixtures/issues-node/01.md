## やること

vitest と Cloudflare Workers の試験環境を入れ、`npm test` を Issue 駆動キットのテストの入口（`scripts/test.mjs`）につなぎ、最初の試験を 1 本通す。

## 元の文書

- `docs/guides/procedures/node-test-procedure.md`（テストの入口の使い方・テストを書く場所）
- `docs/guides/decisions/test-plan.md`（L1 単体・L2 結合）
- `docs/03-roadmap.md` の Phase 1（正常系・異常系をテスト）
- `docs/api-contract.md` の `GET /health`

## 合格の条件

- `devDependencies` に `vitest` と `@cloudflare/vitest-pool-workers` があり、どちらも版を固定している（`^`・`~` を付けない）。版の組み合わせは公式の案内で確かめる
- `package.json` の `scripts.test` が `node scripts/test.mjs` を呼ぶ。`.nvmrc` が `22.14.0`
- テスト「GET /health が 200 と ok を返す」があり、Workers の実行環境（`@cloudflare/vitest-pool-workers`）で `src/worker.ts` を呼んで通る
- `node scripts/test.mjs` の最後の行が `Result: PASS`
- 点検 `node scripts/issue-run/doctor.mjs` に `NG` の行が無い
- `src/worker.ts` と `migrations/` を変えていない

```js
// 守る: src/worker.ts
// 守る: migrations/0001_initial.sql
import { readFileSync, existsSync } from 'node:fs';
import { spawnSync } from 'node:child_process';
import { runTests, requireTests, check, gitClean, done } from './scripts/issue-run/check-lib.mjs';

// パッケージの設定のファイルはこの Issue で直すので、名前を分けて組み立てて指す（パスをそのまま書くと、注釈の中でも守るファイルになり、直せなくなる）
const pkgFile = ['package', 'json'].join('.');
const pkg = JSON.parse(readFileSync(pkgFile, 'utf8'));
const dev = pkg.devDependencies ?? {};
for (const name of ['vitest', '@cloudflare/vitest-pool-workers']) {
  check(!!dev[name], `devDependencies に ${name} がある`);
  check(/^\d+\.\d+\.\d+$/.test(dev[name] ?? ''), `${name} の版を固定している（いま: ${dev[name] ?? '無い'}）`);
}
check(/scripts\/test\.mjs/.test(pkg.scripts?.test ?? ''), `npm test が scripts/test.mjs を呼ぶ（いま: ${pkg.scripts?.test ?? '無い'}）`);
check(existsSync('.nvmrc') && readFileSync('.nvmrc', 'utf8').trim() === '22.14.0', '.nvmrc が 22.14.0');

runTests();
requireTests(['GET /health が 200 と ok を返す']);

const doc = spawnSync(process.execPath, ['scripts/issue-run/doctor.mjs'], { encoding: 'utf8' });
const ngs = (doc.stdout ?? '').split(/\r?\n/).filter((l) => l.startsWith('NG '));
check(ngs.length === 0, `点検に NG が無い${ngs.map((l) => `\n    ${l}`).join('')}`);

gitClean(['src/worker.ts', 'migrations/']);
done();
```

## 先に決めておくこと

- テストのファイルは `test/` に置く（`test/health.test.ts` など）。`vitest.config.ts` の `include` もそれに合わせる。
- Workers の試験は `@cloudflare/vitest-pool-workers` の決まった書き方（`wrangler.jsonc` を読む設定）にする。`wrangler.jsonc` の値は変えない。
- 型の確かめ（`npm run typecheck`）がテストのファイルで落ちるなら、`tsconfig.json` に試験用の型を足してよい（`src/` の型は変えない）。

## やらないこと

- `src/worker.ts` の挙動を変える・デプロイする（`wrangler deploy`）
- ほかの試験（次の Issue で書く）
