## やること

初心者向けのガイド `Docs/Guides/Manuals/issue-driven-guide-for-teams.md` に付録（用語集・Issue のひな形・チェックリスト・よくある質問・このリポジトリの文書の案内）を足して仕上げ、リポジトリの README と `Docs/Guides/Manuals/README.md` から辿れるようにする（段 3/3）。

## 元の文書

- 段 1・段 2 の Issue と、そこで書いた 0〜12 章
- `README.md` の「言葉の説明」（用語集の元。ゲームの言葉は一般の言葉に直す）
- `.github/ISSUE_TEMPLATE/claude-run.md`（ひな形の元）
- `Docs/Guides/Procedures/issue-goal-setting.md` の 7 章（札を付ける前の確かめ。チェックリストの元）
- `Docs/Guides/README.md`（置き場の分け方。`Manuals/` は「使う人に渡す説明書」）

## 合格の条件

- 付録が 5 つある: `## 付録 A` 用語集（表の行が 30 以上）／`## 付録 B` Issue のひな形（Web アプリ・業務アプリ向けにそのまま写せる形を 2 つ以上）／`## 付録 C` チェックリスト（`- [ ]` が 20 以上。始める前・Issue を書く前・回した後）／`## 付録 D` よくある質問（`### Q` で始まる問いが 15 以上）／`## 付録 E` このリポジトリの文書の案内（読む順）
- 0〜12 章が残っていて、全体で 50,000 字以上・Mermaid の図が 2 つ以上
- ガイドの中の相対リンク（`](…)` で `http` で始まらないもの）が、全部実在するファイルを指す
- 「TODO」「TBD」「未記入」「次の段で書く」が残っていない
- `Docs/Guides/Manuals/README.md` があり、ガイドへのリンクがある。リポジトリの `README.md` の「まず何を読めばいいか」からガイドへのリンクがある
- 文書だけの Issue: `Assets/`・`Scripts/`・`ProjectSettings/`・`Packages/` を変えない
- 元の文書（下の「守る」）を変えない

```pwsh
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
# 守る: Docs/Reports/2026/10/22/02-kaedevn-issue-run-success-case.md
# 守る: Docs/Reports/2026/10/22/03-issue-driven-history.md
# 守る: Docs/Reports/2026/10/22/04-kaedevn-issue-run-build-history.md
# 守る: Docs/Reports/2026/10/22/05-kaedevn-monorepo-roots.md
# 守る: Docs/Guides/Procedures/issue-goal-setting.md
# 守る: Docs/Guides/Working/issue-driven-development.md
# 守る: .github/ISSUE_TEMPLATE/claude-run.md
# （書かせる文書・README は変数で指す）
$dir = 'Docs/Guides/Manuals'; $name = 'issue-driven-guide-for-teams.md'; $d = "$dir/$name"
if (-not (Test-Path $d)) { Write-Host "まだ無い: $d"; exit 1 }
$t = Get-Content $d -Raw -Encoding utf8
# コードブロックの中の行頭の # は見出しとして数えない（Issue の例・ひな形・コマンドのコメントを章の切れ目と取り違えない）。長さは変えない。'```' の中に '```pwsh' を入れた二重のブロックも、開いた記号の長さで閉じを見る
$fence = ''
$s = (($t -split "`n") | ForEach-Object {
        if ($fence) { if ($_ -match ('^' + $fence + '`*\s*$')) { $fence = ''; $_ } else { $_ -replace '^#', ' ' } }
        elseif ($_ -match '^(`{3,})') { $fence = $Matches[1]; $_ }
        else { $_ }
    }) -join "`n"

foreach ($n in 0..12) { if (-not [regex]::IsMatch($s, "(?m)^## $n\. ")) { Write-Host "章が消えた: ## $n."; exit 1 } }
$sec = @{}
foreach ($a in 'A', 'B', 'C', 'D', 'E') {
    $m = [regex]::Match($s, "(?ms)^## 付録 $a.*?(?=^## |\z)")
    if (-not $m.Success) { Write-Host "付録が無い: 付録 $a"; exit 1 }
    $sec[$a] = $m.Value
}
$rows = ([regex]::Matches($sec['A'], '(?m)^\|(?!\s*-)')).Count - 1
if ($rows -lt 30) { Write-Host "用語集の行が $rows（30 以上）"; exit 1 }
$tpl = ([regex]::Matches($sec['B'], '(?m)^ # 合格の条件')).Count   # ひな形はコードブロックの中なので、行頭の # は空白に置き換わっている
if ($tpl -lt 2) { Write-Host "ひな形が $tpl 個（2 個以上。それぞれに ## 合格の条件）"; exit 1 }
$checks = ([regex]::Matches($sec['C'], '(?m)^\s*- \[ \]')).Count
if ($checks -lt 20) { Write-Host "チェックリストが $checks 項目（20 以上）"; exit 1 }
$qs = ([regex]::Matches($sec['D'], '(?m)^### Q')).Count
if ($qs -lt 15) { Write-Host "よくある質問が $qs 個（15 以上）"; exit 1 }
if ($t.Length -lt 50000) { Write-Host "全体が短い: $($t.Length) 字（50,000 字以上）"; exit 1 }
if (([regex]::Matches($t, '(?m)^```mermaid')).Count -lt 2) { Write-Host 'Mermaid の図が 2 つ未満'; exit 1 }
foreach ($w in 'TODO', 'TBD', '未記入', '次の段で書く') { if ($t.Contains($w)) { Write-Host "残っている: $w"; exit 1 } }
$bad = foreach ($l in [regex]::Matches($t, '\]\(([^)#\s]+)(#[^)]*)?\)')) {
    $p = $l.Groups[1].Value
    if ($p -match '^(https?:|mailto:)') { continue }
    if (-not (Test-Path (Join-Path $dir $p))) { $p }
}
if ($bad) { Write-Host "リンク先が無い: $($bad -join ', ')"; exit 1 }
$mr = "$dir/README.md"
if (-not (Test-Path $mr) -or (Get-Content $mr -Raw -Encoding utf8) -notmatch [regex]::Escape($name)) { Write-Host "$mr が無いか、ガイドへのリンクが無い"; exit 1 }
$top = 'README' + '.md'
if ((Get-Content $top -Raw -Encoding utf8) -notmatch [regex]::Escape("$dir/$name")) { Write-Host 'リポジトリの README からガイドへのリンクが無い'; exit 1 }
if (git status --porcelain -- Assets Scripts ProjectSettings Packages) { Write-Host 'コード・設定を変えている（文書だけの Issue）'; exit 1 }
Write-Host 'OK'
exit 0
```

## 先に決めておくこと

- 読む人・書き方・作者の経験・数字の引き方は段 1 の Issue と同じ。
- 用語集は README の「言葉の説明」をもとに、ゲームの言葉（Unity・UE・バッチモードなど）は一般の言葉（CI・テストランナー・ビルド など）に置き換えるか、「元の事例の言葉」と分けて書く。
- 付録 B のひな形は `.github/ISSUE_TEMPLATE/claude-run.md` の欄に沿い、確認コマンドの欄に `npm test`・`pytest` などの例を入れる。
- 付録 D の質問は、テストユーザーが聞きそうなこと（費用・セキュリティ・既存のコードに使えるか・テストが無いプロジェクトでどう始めるか・CI との関係・AI が間違えたときの責任・どれくらいの大きさの仕事を任せられるか・Claude 以外の AI でもできるか など）。答えは元の文書の事実に基づき、分からないことは「まだ試していない」と書く。
- リポジトリの README の変更は「まず何を読めばいいか」の表にガイドの行を足すだけ。ほかの行は変えない。
- `Docs/Guides/Manuals/README.md` は新しく作る（Manuals に何があるかの一覧。`Docs/Guides/README.md` の決まり）。

## やらないこと

- 実装・元の文書の書き換え（README の 1 行と Manuals の README の新設は除く）
