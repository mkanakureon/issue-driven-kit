## 合格の条件

- 設計書が `Docs/Guides/Working/scape-m1-detailed-design.md` にあり、全体で 20,000 字以上・見出し 1 が 1 つ
- 次の節がある: `## 0.` ゴールと合格の条件（M1-1〜M1-8 を全部挙げ、どの段のどのテスト・確認コマンドで確かめるかの表）／事実の確認（使う Unity の API と設定を、このプロジェクトの版で確かめた根拠）／アセンブリとフォルダー／クラスの一覧／データの形（撮影の設定の JSON・`assets.json`）／テストワールドの寸法／キーと入力／撮影と自動撮影の引数／書き出しの脚本／テストの一覧／Issue の分け方
- テストの名前（`KaedeScapeBuii.Tests.` で始まる「名前空間.クラス.メソッド」）が 15 個以上あり、EditMode と PlayMode の両方を含む
- Issue の分け方の節に、実装の Issue（S1・S2・S4・S6a・S6b）ごとの確認コマンドの案（```pwsh）が 5 つ以上ある
- Mermaid の図が 1 つ以上
- 文書だけの Issue: `Assets/`・`Scripts/`・`Packages/`・`ProjectSettings/` を変えない
- 基本設計書（下の「守る」）を変えない

$dir = 'Docs/Guides/Working'; $d = "$dir/scape-m1-detailed-design.md"
if (-not (Test-Path $d)) { Write-Host "まだ無い: $d"; exit 1 }
$t = Get-Content $d -Raw -Encoding utf8
# コードブロックの中の行頭の # は見出しとして数えない（開いた記号の長さで閉じを見る）
$fence = ''
$s = (($t -split "`n") | ForEach-Object {
        if ($fence) { if ($_ -match ('^' + $fence + '`*\s*$')) { $fence = ''; $_ } else { $_ -replace '^#', ' ' } }
        elseif ($_ -match '^(`{3,})') { $fence = $Matches[1]; $_ }
        else { $_ }
    }) -join "`n"

    if (-not [regex]::IsMatch($s, "(?m)^##+ .*$([regex]::Escape($w))")) { Write-Host "節が無い（見出しに「$w」）"; exit 1 }
}
foreach ($n in 1..8) { if ($t -notmatch "M1-$n") { Write-Host "合格の条件 M1-$n が無い"; exit 1 } }
$tests = @([regex]::Matches($t, 'KaedeScapeBuii\.Tests\.[A-Za-z0-9_.]+\.[A-Za-z0-9_]+') | ForEach-Object { $_.Value } | Select-Object -Unique)
if ($tests.Count -lt 15) { Write-Host "テストの名前が $($tests.Count) 個（15 個以上）"; exit 1 }
if (-not ($tests -match 'EditMode') -or -not ($tests -match 'PlayMode')) { Write-Host 'テストの名前に EditMode と PlayMode の両方が無い'; exit 1 }
# 「Issue の分け方」の節（次の ## まで。コードブロックの中の見出しは数えない $s で切る）の中の ```pwsh の数
$m = [regex]::Match($s, '(?ms)^##+ [^\n]*Issue の分け方.*?(?=^## |\z)')
$pw = ([regex]::Matches($m.Value, '(?m)^\s*```pwsh')).Count
if ($pw -lt 5) { Write-Host "Issue の分け方の節の確認コマンドの案が $pw 個（5 個以上）"; exit 1 }
if (([regex]::Matches($t, '(?m)^```mermaid')).Count -lt 1) { Write-Host 'Mermaid の図が無い'; exit 1 }
if (git status --porcelain -- Assets Scripts Packages ProjectSettings) { Write-Host 'コード・設定を変えている（文書だけの Issue）'; exit 1 }
Write-Host 'OK'

## 先に決めておくこと

- **決定済み**（基本設計 10 章）: D1 2K = 2560×1440・D2 16:9 だけ・D3 一人称だけ・D5 最初はアセットを入れない（M1）。M1 の範囲・キー・テストワールドの中身・合格の条件 M1-1〜M1-8 は基本設計 11.1 のとおりで、変えない。変えたくなったら設計書に「基本設計への提案」として書き、基本設計書は直さない（直すのはユーザーが決める）。
- **事実を先に確かめてから書く**（design-cycle §2）。少なくとも次を、このプロジェクトの版（Unity 6000.6.6f1・Input System 1.20.0）で確かめ、根拠（ドキュメントの頁・パッケージの中のファイル・試しに書いたコードの結果など）を書く:
  - 物理カメラ（`usePhysicalProperties`・`sensorSize`・`focalLength`・`gateFit`）で 4.2 の画角になるか
  - RenderTexture に描いて読み出す撮り方で、UI Toolkit の画面が写らないこと・Linear の色空間で PNG の色が正しいこと
  - PlayMode のテストで Input System の入力を与える方法（`InputTestFixture` を使うなら、`Packages/manifest.json` に `testables` が要るかどうか。要るなら、その変更は実装の Issue で行うと書く）
  - バッチモードで Windows の EXE を書き出す方法（`BuildPipeline.BuildPlayer`・`-executeMethod`）と、成功・失敗の見分け方
  - EXE に渡したコマンドラインの引数（`-scape-autoshot`）を読む方法と、撮った後に終わる方法
- **Issue の分け方**は基本設計 12.2 の #B〜#F（S1 → S2 → S4 → S6a → S6b を前提でつなぐ）に沿う。各 Issue の確認コマンドの案は、`unity-test.ps1 -Filter` で決めたテストの名前を指し、テストの `.cs` を「守る」に入れる形（`issue-goal-setting.md` 4.4）。S6b の案は EXE の書き出しと `-scape-autoshot` の起動まで。
- テストの名前空間は `KaedeScapeBuii.Tests.EditMode` と `KaedeScapeBuii.Tests.PlayMode` を推す（いまの `SmokeTests` は `KaedeScapeBuii.Tests`。そろえ方も書く）。
- 書き方: 日本語。表と図を使う。クラス名・メソッド名・ファイル名は英語。
