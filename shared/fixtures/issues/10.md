## やること

KaedeScape（中の名前 Scape）の **S4b** を、実装の Issue がそのまま書けるところまで決めた詳細設計書 `Docs/Guides/Working/scape-s4b-detailed-design.md` を書く（設計書を書く Issue。実装はしない）。

S4b で作るもの（2026-10-22 ユーザー指示。基本設計 D3 の変更）:

1. **歩くのは三人称**。自キャラはカプセルの人型。動かし方は MMO（ユーザー「移動は MMO の方が分かりやすい」）
2. **撮るときは自キャラの目の位置の一人称**に切り替わる。一人称の間は自キャラを消し、**撮った画像に自キャラは写らない**
3. **一人称に切り替えた後も、位置と向きを微調整できる**（ユーザー「微調整はできるようにして」）
4. 撮ったら、**画面の真ん中に「画像を保存しました」を約 3 秒**出す（失敗したら「保存できませんでした」）。PNG には写らない

## 先に決めておくこと

- **決定済み**（ユーザー・基本設計 D3）: 歩くのは三人称・撮るのは一人称・自キャラはカプセルの人型・撮った画像に自キャラは写らない・一人称で微調整できる・保存の知らせは真ん中に約 3 秒。これは変えない。変えたくなったら「基本設計への提案」として書く（基本設計書は直さない）。
- **推し**（理由を書いたうえで変えてよい）:
  - MMO の動かし方: マウスの**右ボタンを押して動かす**と視点が回る（ふだんはカーソルが出ている。いまの「マウスを動かすとカーソルが固定されて戻らない」をなくす）・**WASD はカメラの向きに**歩く・自キャラは歩く向きを向く・**ホイール**でカメラが近づく／離れる・走る（Shift）・しゃがむ（C）・跳ぶ（Space）は今のまま。ゲームパッドも使えるようにする。
  - 切り替えのキー: **V**（ゲームパッドにも 1 つ）。三人称で Enter を押したときにどうするか（撮らずに一人称へ切り替える、を推す）も決める。
  - 微調整（一人称の間だけ）: ゆっくり動く（例: 歩く速さの 1/8）・高さを上げ下げする（例: Q／E。0.5〜2.0 m は基本設計 3 章）・視点をゆっくり回す（例: Ctrl を押している間は 1/4）。体の当たり判定は効かせたまま（壁の中から撮らない）。どれだけ動けるか（目の位置から何 m まで）を決める。
  - カメラは壁を抜けない（球を飛ばして当たったら手前に寄る）。屋内（`test-indoor` は 10 × 8 m）で確かめるテストを置く。
  - 自キャラを写さない方法: 自キャラを専用のレイヤーに置き、撮影のカメラの `cullingMask` から外す（一人称で見えている絵と PNG が同じになる）。PNG に自キャラの色が出ないことを画素で見るテストを置く（M1 の `UiToolkitPanelIsNotInPng` と同じ形）。
  - **日本語の字**: いまの既定のフォントには日本語の字が無い（M1 詳細設計 0.4）。EXE で「画像を保存しました」が出る方法を、このプロジェクトの版で**測ってから**決める（例: Windows のフォントから `Font.CreateDynamicFontFromOSFont` → `FontAsset.CreateFontAsset`。ファイルを足すなら置き場と利用条件も書く）。無人の回はインターネットから物を取ってこられない（`.claude/issue-run/prompt.md`）ので、要る物があれば「人が用意する物」として書く。
  - 撮影の設定の JSON の `position`・`eyeHeightM` は「撮ったときの一人称の目」の意味のまま変えない（形を変えるなら `schemaVersion` を上げる理由を書く）。
- **既存のテスト**: M1 の 54 本のうち、一人称の歩き・視点・カーソルのものは変わる。変えるテストは、新しい期待値を 9 章と同じ形の表に書き、実装の Issue の確認コマンドで「変えないテストの `.cs` は守る・変えるテストは名前を変数で指す」形にする（`issue-goal-setting.md` 4.4）。
- **Issue の分け方**: 実装を 1 つにするか、2 つ（三人称と撮影の一人称／保存の知らせと日本語の字）に分けるかを決め、それぞれの確認コマンドの案を書く。M1 と同じ累積の形（M1 の変えないテストと S4b の新しいテストが全部 Passed）にする。最後の Issue は EXE を書き出し直し、`-scape-autoshot` で 3 枚撮れることまで（M1-6・M1-7 を壊さない）。説明書 `kaedescape-user-manual.md` の操作の章を直すことも、実装の Issue の「やること」に入れる。
- 事実を先に確かめてから書く（design-cycle §2）。少なくとも、三人称のカメラの当たり判定の API・レイヤーとカリング・UI Toolkit で日本語の字を出す方法・PlayMode のテストで右ボタンのドラッグとホイールを与える方法を、Unity 6000.6.6f1・Input System 1.20.0 で確かめ、根拠を書く。試しは `%TEMP%` の使い捨てのプロジェクトで行う。
- 書き方: 日本語。表と図を使う。クラス名・メソッド名・ファイル名は英語。
