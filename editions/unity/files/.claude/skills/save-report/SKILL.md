# レポート保存 Skill（Unity / KaedeScapeBuii 用）

作業の振り返り・設計文書・調査結果・**撮影手順やシーン設定のメモ**などを `Docs/Reports/` に保存する。

このプロジェクトは Unity 6 の C# プロジェクト。文書は Unity が取り込まない `Docs/` 配下に置く（`Assets/` に置くと取り込まれ `.meta` ができる）。kaedevn（UE）の save-report と同じ規則。

## 保存先ルール

```
Docs/Reports/{年}/{月}/{日}/{連番}-{タイトル}.md
```

例: `Docs/Reports/2026/10/22/01-claude-setup-report.md`

- **年月日**: 今日の日付を使う（`YYYY/MM/DD`、ゼロ埋め）
- **連番**: その日のフォルダ内の**最大の番号 + 1**（ゼロ埋め2桁）。
  **ファイル数ではなく最大値で決める**——欠番があると数え方では衝突する。
  **書く直前に `ls` する。** kaedevn で 2026-08-19 に別セッションと同じ日に書いて3回ぶつかった
  （04・06・08・11）。番号は早い者勝ちに見えて、**連番でひとつの話になっている側を崩さない**のが優先。
  ぶつかったら、単独の文書のほうを空き番号へ動かす（`git mv` で履歴を繋ぐ）。
- **タイトル**: 英語ケバブケース、内容を簡潔に表す
- パスは**いまの worktree のルート**基準（別 worktree へ保存しない）

### 種別サフィックス

タイトルの末尾に種別を付けて区別する（サブフォルダーは作らない）。

| 種別 | サフィックス | 例 |
|---|---|---|
| 計画書 | `-plan` | `03-scene-plan.md` |
| 設計書・仕様書 | `-spec` / `-design` | `01-shot-spec.md` |
| 実装・作業レポート | `-report` | `06-lighting-pass-report.md` |
| リファレンス（一覧・コマンド集） | `-reference` | `01-console-command-reference.md` |
| 手順書・操作説明書 | `-guide` / `-procedure` | `04-highresshot-guide.md` |
| ステータス報告 | `-status` | `08-scene-status.md` |
| 撮影記録・ショットリスト | `-capture` / `-shotlist` | `03-vn-background-capture.md` |
| シーン／カメラ設定メモ | `-scene` / `-camera` | `02-restaurant-camera-scene.md` |

## 手順

1. 今日のフォルダを確認: `ls Docs/Reports/YYYY/MM/DD/`
2. 既存ファイルの**最大番号 + 1** を連番にする（`ls` して確認。ファイル数で決めない）
3. フォルダがなければ作成: `mkdir -p Docs/Reports/YYYY/MM/DD`
4. ファイルを作成

## デフォルト保存先のルール

**保存先が明示されていない場合、常に `Docs/Reports/` を使う。**

- 「ここに保存して」→ `Docs/Reports/` に保存
- 「文書を作って」「表を作って」「まとめて」「撮影手順を残して」など、保存先の言及がない場合も `Docs/Reports/` に保存
- 別の場所への保存は、ユーザーが明示的にパスを指定した場合のみ

## 書き込み禁止ディレクトリ

**以下のディレクトリには文書を書き込まない。**

| ディレクトリ | 理由 |
|---|---|
| `Assets/` | Unity が取り込む。`.md` を置くと `.meta` ができ、ビルドにも入りうる |
| `Library/` `Temp/` | Unity の生成物。再生成で消える |
| `Logs/` | ログ（追跡しない）。スクリプトの出力の置き場 |
| `Docs/InSpecs/` | **人が書く入力の文書の置き場**。Claude は読むだけで、書き換えない・作らない（入力から作った文書は `Docs/Reports/` へ） |

- 種別（仕様/設計/レポート/撮影記録）に関わらず、Claude が作成する文書はすべて `Docs/Reports/` に保存する
- スクリーンショット実体（`Logs/Screenshots/...` など）を文書から参照するのは可。文書本体は `Docs/Reports/` に置く

## 既存ファイルの扱い

会話中にすでにプロジェクト直下などへ作成されてしまった `.md` がある場合：

- 移動はしない（既存ファイルはそのままにする）
- 代わりに `Docs/Reports/` へ内容をまとめたレポートを作成する

## トリガー

以下のような指示で発動する:

| ユーザーの表現 | 動作 |
|---|---|
| "振り返り文書を作成して" | 直前の作業内容をレポートにまとめて保存 |
| "レポート書いて" | 同上 |
| "設計文書を保存" | 設計内容をレポートにまとめて保存 |
| "撮影記録を残して" | 撮影した構図・カメラ設定・出力先をまとめて保存 |
| "シーン設定をメモして" | カメラ高さ・FOV・ライティング等の設定を保存 |
| "Docs/Reports に保存して" | 明示的な保存先指定 |
| "まとめを書いて" | 作業のまとめをレポートにまとめて保存 |
| "文書を保存して" | 作成・編集した .md ファイルを保存 |
| "ここに保存して" | 直前に作成した文書を Docs/Reports に保存 |
| "保存して" | 直前に作成・編集した .md ファイルを Docs/Reports に保存 |
| "文書作成して" / "ドキュメント保存して" | 作業内容を文書化して Docs/Reports に保存 |

### 重要: 暗黙のトリガー

ユーザーが「保存」「文書」「ドキュメント」「md」「まとめ」「撮影記録」「シーン設定」などのキーワードを含む指示をした場合、
保存先が明示されていなくても `Docs/Reports/` を保存先とみなして発動する。

## レポートのフォーマット

```markdown
---
generated_by: Claude {現在のモデル名}
date: {YYYY-MM-DD}
type: {report | spec | plan | guide | status | reference | capture | scene}
project: KaedeScapeBuii
---

# タイトル

> Generated by Claude {現在のモデル名} — {YYYY}年{M}月{D}日

## 背景
（なぜこの作業／撮影が必要だったか）

## 方針 / 設定
（アプローチ。撮影なら カメラ位置・回転・FOV・解像度 などの数値）

## 手順
（再現できるステップ。エディタ操作やコンソールコマンドを具体的に）

## 成果物 / 出力先
| # | ファイル | 内容 |
|---|---------|------|
| 1 | `Logs/Screenshots/shot-001.png` | 構図メモ |

## 教訓 / 次回への申し送り
（今後に活かせるポイント）

---

> この文書は Claude {現在のモデル名} が生成しました。内容の正確性は人間のレビューを経て確認してください。
>
> Claude {現在のモデル名} — Anthropic
```

### ヘッダー（YAML frontmatter）— 必須

| フィールド | 値 | 説明 |
|-----------|-----|------|
| `generated_by` | `Claude {現在のモデル名}` | 生成したモデル名（例: `Claude Opus 5.5`） |
| `date` | `YYYY-MM-DD` | 生成日 |
| `type` | サフィックスに対応する種別 | `report`, `spec`, `plan`, `guide`, `status`, `reference`, `capture`, `scene` のいずれか |
| `project` | `KaedeScapeBuii` | 固定値 |

### フッター（署名ブロック）— 必須

- `---` で本文と区切る
- 1行目: 免責（「人間のレビューを経て確認してください」）
- 2行目: 空の引用行（`>`）
- 3行目: モデル署名 `Claude {現在のモデル名} — Anthropic`
- `{現在のモデル名}` にはセッション実行時の実際のモデル名を記入する（例: `Opus 5.5`、`Sonnet 5.5`）

### その他のルール

- セクションは内容に応じて取捨選択する（全部必須ではない）
- 撮影・シーン系の文書では、カメラの **位置・回転・FOV・解像度・出力パス** を必ず数値で残す（後で同じ構図を再現するため）
- 本文は日本語、コード・識別子・パスは英語
