# 生成 AI の CLI と MCP をどう使うか — 方針

- 元: Issue 駆動キット（Node 版）。キットの元のリポジトリ（KaedeScapeBuii・kaedevn）で決めて、実際に Issue を合格させた方針を、Node.js＋TypeScript 向けに書き直した
- 対象: このリポジトリで、Claude Code などの生成 AI が使う道具（CLI・MCP）
- これが正。変えるときはこの文書を書き換える（追記で例外を足さない）

---

## 0. 結論（先に）

| # | 決めごと | ひとことで |
|---|---|---|
| G1 | **AI が触る口は「コマンドとファイル（JSON・テストの結果・ログ）」にする** | MCP が無くても全部できる形を保つ |
| G2 | **Issue の無人実行（`issue-run`）では MCP を使わない** | テスト・型の確かめ・ローカルの起動を、コマンドだけで回す |
| G3 | **外のサービス（クラウドの管理画面・DB）を操る MCP は、いまは入れない** | 入れるときは対話の時だけ・使い方の規則つき（3 章） |
| G4 | **自作の MCP は「AI に動いているアプリを操らせる」必要が出たときだけ作る** | 道具を数個に絞り、他の道具を全部外して動かす（4 章） |
| G5 | **作るアプリの中から生成 AI を呼ばない**（それが作る物の目的でない限り） | 実行時に API を呼ばない。AI が見たいものは、Claude Code がファイルを読む |
| G6 | **権限は狭めるだけ・定額プランだけ** | `deny` で断る。`--dangerously-skip-permissions` は使わない。API キーをファイルに置かない |

元のリポジトリでは、G1・G2 のとおりに作り、MCP を 1 つも使わずに Issue 13 件が全部合格した。

## 1. 言葉

| 言葉 | 意味 |
|---|---|
| CLI | コマンドで動かす道具。ここでは `claude`（Claude Code）・`gh`（GitHub）・`node scripts/*.mjs`・`npm`・`wrangler` などのツール |
| MCP | Model Context Protocol。AI に「道具」を足す決まり。MCP のサーバーが道具（例: 「DB に問い合わせる」）を出し、AI がそれを呼ぶ。サーバーは別のプロセスで、相手が動いている間だけ使える |
| 無人の回 | `scripts/issue-run/issue-run.mjs` が Issue ごとに `claude -p` を起動して、人なしで進める回（`docs/guides/working/issue-run.md`） |
| 契約面 | AI と道具の境目。「何を渡せば何が返るか」が決まっている所 |

---

## 2. なぜ「コマンドとファイル」か（G1・G2）

### 2.1 合否は機械で読めるファイルで決める

- 合格の条件は確認コマンドの終了コードと `Result:` 行で決める（CLAUDE.md 原則4）。
- テストの結果は JUnit の XML（`.issue-run/test-results/junit.xml`）、型の確かめは終了コード、API の確かめは応答の JSON。どれもファイルかコマンドの結果なので、無人の回の確認コマンドが読める。MCP の返答は会話の中にしか残らず、確認コマンドから読めない。

### 2.2 人も AI も同じ口を使う

コマンドとファイルなら、人がターミナルで打っても、AI が打っても、無人の回が打っても同じ結果になる。MCP を入れるときも、MCP から**この口を呼ぶ**形にし、MCP だけにある機能を作らない。

### 2.3 外のサービスに触る操作は、無人の回で断る

デプロイ・本番の DB・課金のある操作は、取り返しがつかない。無人の回の設定（`.claude/issue-run/settings.json`）で `wrangler deploy`・`npm publish` などを断っている。MCP で外のサービスに触れると、この断りをすり抜ける道ができる。

---

## 3. 外のサービスを操る MCP（G3）

### 3.1 いまの決定: 入れない

- いまは要らない。作る・確かめる作業は、ローカルのコマンド（`npm`・`node`・ローカルで動かすツール）でできる。
- クラウドの管理画面・DB・課金を操る MCP は、このリポジトリでは入れておらず、**道具の範囲・権限・どの環境につながるかを確かめていない**（6 章）。

### 3.2 入れるとしたら（この規則で）

| 規則 | 理由 |
|---|---|
| 対話のセッションだけで使う。無人の回では使わない | 2.3 |
| 呼ぶ前に、**どの環境（ローカル・試し・本番）につながっているか**を読み取りの道具で確かめる | 接続先を取り違えると、本番を操ってしまう |
| 読み取りの道具から使う。書き込みの道具は 1 つずつ・人の了承の後 | 元に戻せないことがある |
| `--dangerously-skip-permissions` は使わない | MCP は外のサービスに広く直に触れる |
| 「道具が見えない」を「サービスが止まった」と思い込まない | 道具の一覧を読み直せば戻ることがある |

## 4. 自作の MCP（G4）

### 4.1 作るのはこのときだけ

**動いているアプリ（ローカルの API・画面）を、AI に操らせて確かめたい**とき。たとえば、CLI のモックでは再現できない、人の操作の順番の試験。

ふつうは要らない。確かめたい要求を JSON にして、ローカルで起動した API にコマンドで送り、応答をファイルに残せば、無人の回でも回る。

### 4.2 作るときの形（元のリポジトリの手本）

元のリポジトリ（kaedevn）は、AI に初めて遊ぶ人の役をさせる試験のために、自作の MCP のゲートウェイを作った。そこで決めたこと:

| 決めたこと | 中身 |
|---|---|
| 道具を絞る | 出す道具は 4 つだけ。ファイルの取得・URL・git・デバッグの道具は出さない |
| 他の道具を外す | `claude -p` に `--tools ""`（組み込みの道具なし）・`--strict-mcp-config --mcp-config <ゲートウェイだけの設定>`・`--disable-slash-commands`（スキルなし）・`--setting-sources ""` を付ける |
| 余計な情報を見せない | 空の設定フォルダーと、`.git` も CLAUDE.md も無い一時フォルダーで起動する。環境変数は消してから要るものだけ渡す |
| 相手は起動側が決める | アプリ・データ・ログの置き場は起動の引数で決める。AI の側からは指せない |
| 記録は AI から見えない所へ | 呼ばれた道具と返答をログのフォルダーに残す |
| 隔離を確かめてから始める | 起動前の点検で、実際に送られた中身から隔離を確かめる。確かめられなければ、正式な結果にしない |

作るときは、中では 2 章の口（コマンド・API）を呼ぶだけにする。MCP にしかない機能を作らない（2.2）。

## 5. 無人の回の `claude` の使い方（G6）

`scripts/issue-run/issue-run.mjs` が `claude -p` に渡しているもの:

```text
claude -p --output-format json --permission-mode auto --permission-prompts none
       --disallowed-tools AskUserQuestion --settings <.claude/issue-run/settings.json から作った設定>
       [--session-id | --resume <id>] [--model <モデル>]
```

| 決めごと | 中身 |
|---|---|
| 指示は標準入力で渡す | 引数で渡すと改行と引用符が壊れる |
| 権限は狭めるだけ | `.claude/issue-run/settings.json` の `deny`（push・履歴の書き換え・削除・Issue への書き込み・CLAUDE.md と `.claude/` の書き換え・`docs/inspecs/` の書き換え・デプロイ・公開など）。auto mode の判定にまかせない |
| 設定が効いたかを確かめてから始める | `-p` は壊れた設定を黙って無視する。起動前に Stop hook と `deny` が効くことを実際に試す（`probe.json`・`probe-stop-hook.txt`） |
| 返答を「合格」まで終わらせない | Stop hook。報告が「合格」になったら確認コマンドを回す |
| 使わないもの | `--dangerously-skip-permissions` |
| 料金 | 定額プランのログインで回す。API キー（従量課金）をファイルに書かない |

## 6. まだ確かめていないこと

| 事柄 | いまの扱い |
|---|---|
| 外のサービスを操る MCP の道具の範囲・権限・接続先 | 入れない（G3）。入れたくなったら、先にこれを測って、この文書を書き換える |
| ユーザーの Claude の設定にある MCP（claude.ai のコネクター）が、無人の回の `claude -p` にも載るか | 確かめていない。元のリポジトリでは使われなかった。気になるなら、`issue-run.mjs` に `--strict-mcp-config` を足して外す（未採用の改善） |

## 7. 決定を変えるとき

| こうなったら | 見直すもの |
|---|---|
| 動いているアプリを AI に操らせる試験が要る | G4。4.2 の形で作る |
